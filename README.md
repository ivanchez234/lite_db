# LiteDB — Гибридная СУБД с колоночным хранением и конвейерным сжатием

**LiteDB** — это учебный проект, реализующий полноценную клиент-серверную систему управления базами данных, написанную с нуля на C++17. Основная цель — создать высокопроизводительную базу данных, превосходящую SQLite по скорости операций и обеспечивающую прозрачную интеграцию с современными ORM (SQLAlchemy) через стандартный драйвер DB‑API 2.0.

---

## ✨ Ключевые особенности

- **Гибридная модель хранения** — горячие данные (вставки) хранятся в памяти в строковом формате для максимальной скорости записи, а при сбросе на диск автоматически трансформируются в колоночный формат для высокой плотности хранения.
- **Многоуровневый конвейер сжатия** — семантическое сжатие (дельта‑кодирование, битовая упаковка) + физическое сжатие (Deflate/Zlib) дают кратное сокращение размера файлов на диске.
- **In-Memory индекс** на основе хеш-таблиц (`std::unordered_map`) обеспечивает константное время доступа O(1) к записям по первичному ключу.
- **Кастомный бинарный формат** с хешированием ключей — позволяет извлекать нужные поля без полного парсинга записи (Zero‑Parse Extraction).
- **Многопоточный TCP-сервер** с конкурентной обработкой клиентских подключений (отдельные потоки на соединение).
- **Драйвер по стандарту Python DB‑API 2.0 (PEP 249)** и **кастомный диалект для SQLAlchemy** — работа с БД через ORM становится полностью прозрачной.
- **Поддержка мягкого удаления** (Tombstones) без немедленной перезаписи дисковых блоков.

## 🧱 Архитектура

Система состоит из пяти основных уровней:

1. **Storage Engine (движок хранения)**  
   - In-Memory индекс (хеш-таблица)  
   - Гибридное хранение (row-based в памяти, columnar на диске)  
   - Алгоритмы сжатия: LZ4, Zlib (Deflate + Huffman), дельта-кодирование, битовая упаковка  
   - Кастомный бинарный формат с хешированными ключами  

2. **Network Transport (сетевой слой)**  
   - C++ TCP-сервер (прослушивает порт)  
   - Многопоточная обработка подключений (`std::thread`)  
   - Бинарно-текстовый протокол для передачи SQL-запросов и результатов  

3. **SQL Parser (транслятор запросов)**  
   - Разбор подмножества SQL (CRUD) на основе регулярных выражений (`std::regex`)  
   - Диспетчеризация команд (INSERT, SELECT, UPDATE, DELETE)  
   - Преобразование запросов в вызовы Storage Engine  

4. **Python DB-API 2.0 Driver**  
   - Класс `Connection` — управление TCP-сокетом с C++ сервером  
   - Класс `Cursor` — выполнение запросов, десериализация результатов в список кортежей  
   - Методы `execute()`, `fetchone()`, `fetchall()`  

5. **SQLAlchemy Dialect**  
   - Кастомный диалект `LiteDBDialect`, регистрирующий протокол `litedb://`  
   - Адаптация генерации SQL под возможности базы данных  
   - Прозрачная работа с ORM: `session.add()`, `session.query()` и т.д.

Весь стек работает сквозным образом:  
`ORM → Диалект → Драйвер → TCP-сокет → C++ Парсер → Storage Engine (декодирование/сжатие) → Диск`

## 🛠 Технологический стек

| Компонент | Технологии |
|-----------|------------|
| Язык | C++17 |
| Сборка | CMake, MinGW/GCC |
| Сжатие | zlib (Deflate/Huffman), LZ4 |
| Сеть | Native TCP Sockets |
| Парсинг SQL | `std::regex`, строковые алгоритмы |
| Индексы | `std::unordered_map` |
| Синхронизация | `std::mutex`, `std::lock_guard` |
| Тестирование | Python (socket-скрипты) |
| Драйвер Python | PEP 249, сокеты |
| ORM | SQLAlchemy (кастомный диалект) |

## 🚀 Сборка и запуск

### Требования
- Компилятор с поддержкой C++17 (GCC 7+, MinGW)
- CMake 3.10+
- Библиотека zlib (разработочная)
- Python 3.6+ (для драйвера и тестов)

### Сборка сервера
```bash
git clone https://github.com/your-username/LiteDB.git
cd LiteDB
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
make -j4
